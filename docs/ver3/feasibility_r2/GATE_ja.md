## 3. 三脚の位相は、座標だけで独立指定しない

同じ向きのJansen脚を左右三本ずつ置きます。軸の前後ピッチ84mm、足の左右半幅64mm、リンク尺度0.7を骨格入力としました。外側二駅と中央駅で、左右クランクの0/180°を入れ替えます。

基準案はモジュール1.5・28歯の**主軸―遊び歯車―主軸―遊び歯車―主軸**です。隣接中心距離42mm、主軸間84mm。二つのかみ合いで反転が戻り、三主軸は同方向・同位相になります。クランクはD穴に対して0°／180°の二つの取付形状を使います。軸端の外側へ脚を置くため、AB/ACの動く平面を貫通する主軸を前提にしません。

平歯車の減速段はモジュール1.25、圧力角20°、ピニオン20歯、歯幅5mm、名目円周バックラッシ0.30mm。歯数から中心距離・歯先厚・接触比を計算しています。**解析的な歯形指標と、完成実体の全周干渉・公差・工具アクセス検査は別**です。

同方向で同位相の三足は、剛体モデルでは同一の動きをするため三脚内の拘束が整合します。一方、足裏の円弧転がり、地面との摩擦、軸位相誤差は未検証です。[運動学JSON](gait.json) に、0.5°格子に加えて接地切替の両側を記録しました。条件付きの上下動は約1.21mm、幾何から求める前進は約94mm/クランク周です。

**これは「94mm歩いた」という実験結果ではありません。** 切替で水平・鉛直の速度係数に不連続が残ります。反発・足裏変形・慣性を解かないこのモデルだけで、30cm連続歩行や実際の滑り3mm以内を合格にしません。重心 `[0,-26,50]mm` も新CADによる集計値ではなく、満たす必要がある設計目標です。

### 同期機構を一度だけ限定比較

[2本の直交連結ロッドとの比較](synchronization_comparison.svg) / [入力と結果](synchronization_comparison.json) を追加しました。三つのクランクピンを結ぶロッドを二組用い、二組のピンを0/90°にずらします。三軸は実際に閉リンクでつながり、片方のロッドが死点でも他方の腕が消えません。

0.25°格子での閉路残差は数値丸め内、相対位相拘束の最小特異値は8mm/radでした。玉軸受は4個減りますが、6個の摺動関節と二重閉路の寸法誤差が増えます。予荷重0/1/3Nを感度入力に含め、摩擦が摩擦反力を増やす影響も扱っています。必要入力の低下は条件付きで概ね1～2割であり、桁違いの改善ではありません。

国内軸受4個の差額は748円ですが、追加のスリーブを最低ロットで買えばその節約を打ち消すことがあります。**予荷重ゼロのセルだけを選んで採用確定しません。** 小さい同期・はめあい試験片へ進める候補とし、既存のA/B/C主図は5歯車バスのままです。

## 4. 風→反力→摩擦→変形を同じ荷重条件で計算

各脚は6個の平面剛体です。力・モーメント釣合いから関節反力を求め、反力、ジャーナル半径、相対角速度から始動摩擦を計算します。A/Pの国内スリーブは外径6mmなので摩擦半径3mm、自由関節の外径4mm品は半径2mmです。

風の水平力は歩行を助ける方向に利用せず、向かい風側の荷重に置きます。鉛直空気力の不利側も別に加えます。**風の作用高さ・位置と、必要入力トルクの符号を使って支持圧中心（COP）を動かし、法線荷重と各脚の反力を再計算**します。入力トルク自身も全身の外力モーメントなので、反力／摩擦との固定点を反復して求めます。これは必要な駆動を与えたときの荷重であって、風がその入力を実際に供給できるという意味ではありません。速度・幅の各セルでも負荷を計算し直しており、8m/s時の要求トルクを固定したまま全セルへ使い回しません。

低／名目／高抵抗ケースは、ジャーナル摩擦0.05/0.10/0.18、軸受1個の始動抵抗0.1/0.3/1.0Nmm、歯車1かみ合いの効率0.95/0.90/0.80などを共通に使用します。これらは**測定値でも保証された最悪値でもありません**。同期バスのかみ合い・軸受も数えます。

## 5. 流体モデルの出来ること・出来ないこと

局所的なガウス噴流を、風車の有限幅で積分します。8/12/16枚、羽根の曲がり角−20/0/20°、中心／半径0.5／半径0.75だけずらした吹付位置を各27セルで調べました。流れから最初に見える面をレイで選び、その面の法線に対する静的抗力を積分します。戻り側の負トルクも記録します。

HYP_8_20内では16枚・20°・半径0.5の位置が比較上の候補になりました。ただし局所パネル抗力係数1.2も保持係数0.25/0.50/0.75も未校正です。**正のローター係数を全角度に直接与えて自己始動を成立させたものではなく、供給下限は依然 `null` です。**

これはCFD、圧力場、流線場、回転流体解析ではありません。羽根の有限厚さ、軸・端板、漏れ、再循環、噴流自体の変化、乱れ・レイノルズ数依存を十分に扱いません。低次モデルの色付き流速図・圧力図は作っていません。利用可能なPATH上では `simpleFoam/pimpleFoam/pisoFoam/foamRun/SU2_CFD` は見つからず、新しいソルバーは導入していません。

静止トルクと回転中の性能も分けます。回転RPMを与えた歩行動画を自己始動の証拠にしません。速度を二乗で外挿すると風荷重・COP・摩擦も変わるので、**固定負荷から逆算した「必要ReFa風速」や距離は出しません**。

風車の薄壁・端板から質量慣性モーメントの代理値も計算し、減速比の二乗でクランク側へ換算した値を `rotor_mass_proxy` に保存しています。加速時にはこれに角加速度が必要ですが、実加速度は未入力です。歯車・脚を含む全慣性、衝撃、回転中トルクの検証ではなく、慣性を理由に静止死点を越えられるとは扱いません。

## 6. 材料・構造の図

[たわみA](deflection_A.svg) / [B](deflection_B.svg) / [C](deflection_C.svg) は、支点・荷重・部品ID・変形倍率を備えた実計算図です。灰色は原形、色線は梁モデルの変形です。倍率は横軸と同じmm→画素換算に対して定義し、色は各部材の変位0～その最大値です。実機の写真や応力を着色した完成CADではありません。

対象は風車軸、伝達／中間軸、クランク軸、固定ピボット、細いAC部材です。軸受支点は回転を拘束しない単純支持です。固定ピボットだけは根元に対する片持ちモデルで、**M3のコア径を保守的に2.25mmとして計算し、外径6mmの黄銅スリーブを中実鋼とみなしません**。ねじの実コア・等級、ねじ谷の応力集中、印刷ボスの柔らかさは別の製造ゲートです。

6mm D軸は、メーカー図の直径6mm・平面から反対外周まで5.5mmを照合済みです。断面積・重心・最弱方向の曲げ断面二次モーメントを積分し、ねじり剛性は内接／外接円の上下界で扱います。**非円断面のねじり定数を極断面二次モーメントで代用していません。** ねじりの最大せん断応力・降伏は未確定のままです。

鋼のE/G、印刷材E=800/1700/2600MPa、印刷材の応力スクリーニング8MPaなどは条件入力です。冷風だから印刷物性・積層方向・クリープ・疲労を省略してよいわけではありません。ACには別途、偏心圧縮のセカント式・Euler座屈・横荷重を用います。図のAC線は横荷重成分のみで、複合たわみと応力はJSONの別欄です。

軸だけでは曲げ変位は数µm程度、M3コアの固定ピボットは約0.005mmという計算ですが、これで噛合い全体を合格にしません。中心の相対移動と歯幅方向の傾きをバックラッシ量へ換算し、名目0.30mmの半分を軸・支持系の暫定予算にしました。ハウジング・軸受はめあい・印刷公差をまだ加えていません。

## 9. 再現と確認範囲

```sh
python3 -m unittest discover -s scripts/ver3 -p 'test_study_r2.py' -v
python3 scripts/ver3/study_r2.py
python3 scripts/ver3/study_r2.py --verify
```

既存のVer.3用NumPy/SciPyを使用します。FreeCAD 1.1.3とBlenderは既にありますが、この成立性計算はライブCAD場面を操作せず、CFDや新たな大規模アプリも導入しません。

試験は片持ち・両支持・等分布梁の解析解、単位・反力平衡・分割感度、D断面の剛性上下界、リンク閉路、脚の反力トルクと仮想仕事の一致、抵抗力が実際の進行方向へ逆らうこと、風モーメントが法線荷重を変えること、局所噴流の速度二乗／電力三乗則などを対象にします。`--verify` は出典／成果物ハッシュ、図のXML、荷重釣合い、測定トルク定義を照合します。**試験の成功はモデルの実装確認で、実機の物理認証ではありません。**

この版では17項目の自動試験を実行しました。最も上限に近いBについて、クランク格子を0.5°から0.25°へ細分しても必要入力ピークは一致しました。静止噴流の角度／積分レイを0.5°・512本から0.25°・1,024本へ細分したとき、最小トルク代理値の変化は約0.112%でした。これはモデルの数値感度確認で、未校正抗力係数の誤差が0.112%という意味ではありません。全12図は描画後の文字のはみ出しを検査し、代表の梁・風トルク・同期比較を目視しています。

図単位の `manifest.json` には `revisionId / sourceGeometryRevision / designId / loadcaseId / method / units / figureUnits / displayAmplification / resultStatus / sourceHashes` を持たせています。単位欄は生データ、`figureUnits` は図上の単位です。実CADへの対応を表す `isFinalCadGeometry` はすべて `false` です。サイト側で旧第一カットと混在させず、同じ版の図とJSONをひとまとまりで扱ってください。
