# r7床是正版・連続歩行の表示モデル v1

**計算表示であり、実機の歩行実証ではありません。** `manufacturingRelease=false`、実機合格数0、
実自己始動・実30 cm歩行UNKNOWNを保持します。風速から回転数を予測したCFD／衝撃動力学ではありません。

## 追加したモデル

**剛体リンク。** `points_many` と同じ向き付き円交差・固定組立分岐で、任意のクランク角を解析的に閉じます。
脚・ピン・歯車・フレームに頂点補間や非直交の小角写像を掛けません。部品は同じ剛体メッシュ・配置・追跡IDです。
ブラウザーと映像のフレーム書出しは同じ `site/r7-walk-math.js`、同じ版付きJSONを使います。

**接地再整合。** 元の小角写像で求めた鉛直荷重の合力・作用点XYを補間し、これを新しい表示モデルの荷重目標に固定します。
極分解と等価な直交回転、本体高さ、実ガイド軸、二つの半径6 mm円筒パッドで、本体高さと二勾配を再度解きます。
圧縮は床との隙間をガイド軸へ投影した片側接触、法線力は2本のばねの公称合成レート1.764 N/mmを同軸へ投影した値です。
任意に本体を持ち上げた「床逃げ」ではありません。新姿勢の全機構質量・風荷重・摩擦を再収束したものでもありません。
高さ等の解を0.125°刻みで保存し、表示の任意角では姿勢パラメーターだけを補間、接触圧縮とリンクは再計算します。
補間中の合力・モーメント誤差も検査します。

**荷重ロッカー。** 実際の軸回りに左右パッドの軸を等高にする角を使い、許容±5°を超えれば生成を拒否します。
円筒の半径・軸長・左右間隔から最下点を計算します。代表点だけが床上でも端が床下、という判定はしません。

**空中ロッカー：`VISUAL_REST_V1`。** 圧縮がなくなった足では、床から3 mmまでの隙間を使い、
smoothstepで等高角から相対中立角へ戻します。接地側との角度連続性を保つ**表示上の復帰仮定**です。
重心から解いた重力平衡、減衰・ヒステリシス、着地衝撃を予測した受動運動とは主張しません。

**ばね：`PROCEDURAL_COIL_V1`。** 同じ12本の `H_FOOT_SPRING` IDで、上下の実座、線径0.6 mm、
平均半径3.2 mm、6.8巻を保持し、圧縮に従いらせんピッチだけを変えます。
自由長15 mm、作動上限6 mm、幾何上の密着長4.08 mmを検査。端部ピッチは簡略化しています。
未変形CAD線材を丸ごとスケールせず、応力・疲労・実ばねの認証とはしません。

**前進と時間。** 1周期内は保存された積算前進／横移動／ヨーを補間し、周期の繰返しはSE(2)の合成で移動方向も運びます。
任意の一定速度を加えません。元解析の床滑りは未解消です。入力は仮の絶対120 rpm、
入力／クランクの符号付き比はA＋144、B−512、C＋156。入力角は時間から非折返しで求めます。
同じ時間倍率ならBのクランクは実際に遅くなります。映像は全案16×、ブラウザーでは1／4／8／16×を選べます。

|---|---:|---:|---:|---:|---:|
| A | 92.382036 | 3.170179 | 0.790634 | 1.074156 | 6.342434 |
| B | 92.583845 | 3.127876 | 0.718049 | 1.068438 | 5.634264 |
| C | 92.388135 | 3.040939 | 0.746420 | 1.076509 | 6.630170 |

保存値の補間に対する最大の高さ変更はA0.04045／B0.03279／C0.04058 mm、勾配変更は角度近似で
A0.04676／B0.02569／C0.03331°、ガイド圧縮変更は最大0.10179 mmです。

各案5760位相（0.0625°）でパッド接地・圧縮・角度・支持・補間時荷重を検査。
パッド最下点は数値丸め内（約−1.3e−14 mm）、荷重足は3脚以上。支持多角形は6個の足中心から作り、足幅で拡大しません。
鉛直合力誤差は0.01 N未満、水平二軸のモーメント誤差は各1 Nmm未満。
最大リンク長誤差とばね上端の座のずれは1e−8 mm未満、回転直交性誤差は1e−9未満を条件にしています。
さらに元CADの保守的な非接地包絡を全2285点・各720位相（0.5°）で確認します。
二つの円筒パッドだけを別の接触判定にし、ロッカー芯・締結品・ばね・ガードは除外しません。

これは有限標本であり、全可動部の連続衝突判定、製造公差・実床・実風・実摩擦の保証ではありません。
元解析の荷重期間最大滑り約22 mmなどはそのまま残ります。法線オーバーレイはこの表示再整合の値で、接線摩擦やFEM応力の図ではありません。
詳細は `validation_A/B/C.json` と、毎ビルド実行する `site/tests/walking-math.test.mjs` を参照してください。

## 映像・ネイティブと再現

全案4周期、計算上約37 cm。入力120 rpmでの時間はA288／B1024／C312秒、
映像では16×で約18／64／19.5秒です。24 fpsの各フレームをブラウザーと同じ解析式から出力します。
高速軸は非折返しEuler角で動かし、露光中のモーションブラーを使います。表示fps由来の見かけの回転は実速度の計測ではありません。
Blenderは全三案・2285 ID・12本/案のGeometry Nodesばねと編集可能な剛体キーフレームを含みます。
ネイティブのキーフレーム間・ブラーは剛体姿勢の表示補間で、各フレーム間の新しい接触解ではありません。
ネイティブのfloat32量子化とブラウザーのfloat64基準も、別の検証JSONに記録します。
原メッシュの頂点・三角形は一致。ネイティブの代表フレームでは回転直交性2e−6、
全体の角点差0.15 mm、ロッカー実頂点の床下許容0.001 mmを別の表示精度条件にしています。
これを解析的なリンク閉鎖・接触の1e−8 mm条件や製造公差と混同しません。

```bash
# 通常公開ビルド。既存の固定された配布物から生成（Blender/SciPy不要）
python3 site/build.py
npm --prefix site run test:static
npm --prefix site test -- walking.spec.mjs

# 任意：新しい表示解の再計算。正規CAD・接地原本には書き込まない
python3 site/r7_walk_model.py --design C
python3 site/r7_walk_model.py --design A
python3 site/r7_walk_model.py --design B

# 保存JSONから映像を再現。既存Node/Blender/ffmpegを使用し、必ず直列
node site/r7-walk-export.mjs --design C
node site/r7-walk-export.mjs --design A
node site/r7-walk-export.mjs --design B
blender --background --factory-startup --python site/r7_walk_render.py -- --build-native
blender --background --factory-startup --python site/r7_walk_render.py -- --design C
blender --background --factory-startup --python site/r7_walk_render.py -- --design A
blender --background --factory-startup --python site/r7_walk_render.py -- --design B
blender --background --factory-startup --python site/r7_walk_verify_native.py
python3 site/r7_walk_finalize.py
```

動作するライブBlenderには接続しません。各フレームPNGはffmpegへ渡して直ちに消し、大量の画像列を残しません。
日本語の画面注記は既存macOSフォントでアウトライン化し、フォントファイル自体を配布しません。
通常サイトは選択した案のGLB・運動JSONだけを取得、動画も操作時のみ。歩行追加物は別枠16 MB以内、
以前の静的12 MB／旧3D18 MB／r7比較・組立30 MBの上限は維持します。大きなBlender原本はPagesにコピーしません。
操作3Dは全メッシュを残した拡散照明、動画はEEVEEです。画面の再描画間に入力処理の時間を確保し、
GPUが遅い場合も描画フレーム数を「規定時間」として扱わず、実際の経過時間から角度を求めます。
